# แบบฝึกหัดบทที่ 13: รายรับ-รายจ่ายด้วย Provider และ SQLite

ทำตามส่วนปฏิบัติการของเอกสาร โดยปุ่มเพิ่มใช้ข้อมูลตัวอย่างตามโจทย์

## วิธีรัน

```sh
flutter pub get
flutter run
```

เลือก Android emulator/เครื่องจริง หรือรันบน Windows ด้วย `flutter run -d windows` โปรเจกต์นี้ใช้ SQLite แบบ native จึงไม่ได้ตั้งค่าสำหรับ Chrome/Edge

## วิธีใช้

- กด **+** เพื่อเพิ่มรายการ “ค่าอาหาร” จำนวน 120 บาท ประเภทรายจ่าย และวันที่ปัจจุบันโดยตรง
- กดถังขยะและยืนยันเพื่อลบรายการ
- ยอดคงเหลือใต้ AppBar คำนวณด้วย `SUM` ผ่าน `rawQuery`
- เมธอด `updateTransaction` ยังคงอยู่ใน Provider ตามกระบวนการ Update ของแบบฝึกหัด

## โครงสร้างโค้ด

| ไฟล์ | หน้าที่ |
| --- | --- |
| `lib/main.dart` | ตั้งค่า Provider และเปิดหน้ารายการ |
| `lib/models/my_transaction.dart` | โมเดล แปลง Map, enum, วันที่ และ note |
| `lib/providers/transaction_provider.dart` | เปิด SQLite, CRUD, migration, ยอดรวม และการทดลองจับเวลา |
| `lib/screens/transaction_list_screen.dart` | แสดงรายการ ยอดคงเหลือ เพิ่มข้อมูลตัวอย่าง และลบข้อมูล |

ใช้ Provider ติดต่อ SQLite โดยตรงตามสถาปัตยกรรมในส่วนปฏิบัติการ ไฟล์ `lib/helper/database_helper.dart` เดิมจึงไม่ได้ถูกเรียกใช้

## ฐานข้อมูลและการอัปเกรด

ไฟล์ `expenses.db` มีตาราง `transactions` ซึ่งเก็บ `id`, `title`, `amount`, `date`, `type`, `note`

- `date` เก็บเป็น ISO 8601 และ `type` เก็บเป็น `income` หรือ `expense`
- ฐานข้อมูลใหม่สร้างด้วย version 2
- ฐานข้อมูล version 1 ใช้ `ALTER TABLE ... ADD COLUMN note` เพื่อเก็บแถวเดิมไว้ โดย note ของแถวเก่าเป็นข้อความว่าง
- `UPDATE` ไม่เขียนทับ id และส่งค่าระบุแถวผ่าน `whereArgs`
- Android/iOS ใช้โฟลเดอร์ฐานข้อมูลของแอป ส่วน Windows/Linux ใช้ตำแหน่งเริ่มต้นของ sqflite_common_ffi คือ `.dart_tool/sqflite_common_ffi/databases` ในโฟลเดอร์ที่รัน จึงควรเก็บโฟลเดอร์นี้ไว้หากต้องการรักษาข้อมูลเมื่อทดสอบบน desktop

## การทดสอบ

```sh
flutter analyze
flutter test
flutter build apk --debug
```

ชุดทดสอบครอบคลุมโมเดล, CRUD และข้อมูลหลังเปิดใหม่, migration จาก v1, นำเข้าทั้งสองแบบผ่าน Provider, ยอดรวม 3,000 แถว, rollback เมื่อ batch ล้มเหลว, ปุ่มเพิ่มข้อมูลตัวอย่าง, การยกเลิก/ยืนยันลบ และการเพิ่มผิดพลาดแล้วลองใหม่

การทดสอบฐานข้อมูลใช้ SQLite จริงในไฟล์ชั่วคราวแยกจากข้อมูลของแอป ส่วน widget tests ใช้ Provider จำลอง

ตัวอย่างเวลาที่วัดบนเครื่องพัฒนานี้:

| การทดลอง | วิธีแรก | วิธีที่สอง |
| --- | --- | --- |
| นำเข้า 100 รายการ | addTransaction ทีละรายการ: 427.58 ms | batch ใน transaction: 11.74 ms |
| ยอดรวม 3,000 รายการ | SQL SUM: 0.41 ms | อ่านข้อมูลแล้วบวกใน Dart: 1.86 ms |

เวลาเป็นผลการรันทดสอบหนึ่งครั้ง ไม่ใช่ค่ารับประกัน วิธีทีละรายการเรียก addTransaction และโหลดรายการใหม่ทุกครั้งตามโจทย์ ส่วน batch commit และโหลดใหม่ครั้งเดียว ดังนั้นการเปรียบเทียบนี้รวมค่าใช้จ่ายในการโหลดข้อมูลด้วย SQL ส่งยอดรวมกลับค่าเดียว ขณะที่วิธี Dart ต้องรับข้อมูลทุกแถวก่อนวนบวก

ทดสอบเพิ่มเติมบนอุปกรณ์: กด + เพิ่มข้อมูล ปิดแอปแล้วเปิดใหม่ ตรวจว่าแถวยังอยู่ ลบแล้วเปิดใหม่อีกครั้ง สำหรับ migration ให้รันทับแอป version 1 ที่มีข้อมูลอยู่โดยไม่ถอนการติดตั้ง
